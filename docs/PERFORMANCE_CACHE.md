# AI performance cache

The server resolves article analysis and recommendation classification in this order:

1. generated demo preset;
2. Upstash Redis;
3. live AI.

Redis values expire after seven days. Redis is optional and fail-open: missing credentials,
timeouts, and command failures continue to the live AI path.

## Environment

Configure the variables generated by the Upstash integration:

```text
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
```

The helper also recognizes Vercel KV-compatible `KV_REST_API_URL` and
`KV_REST_API_TOKEN` variables. Never commit their values.

## Keys

- `article-analysis:v2:<sha256>` hashes the normalized article title and paragraph text.
- `recommendation:v2:<sha256>` hashes the normalized question, search query, sorted and
  deduplicated choices, and the ordered candidate ID/URL fingerprint.

Bump `v2` when a prompt or output contract changes incompatibly.

## Presets

Generated presets are loaded from `server/demo-cache-presets.mjs`. Keep the maps empty
until results can be produced using the real configured Zhihu and OpenAI services. Do not
hand-author or copy mock classifications into this file.

API responses expose `cacheSource` (`demo-preset`, `redis`, or `live-ai`) and
`timingMs.total` for DevTools and performance verification. These fields are not rendered
in the product UI.
